# 编辑器后端监听的启动、清理与退出

状态：Accepted。

## 问题

编辑器由 MCP 进程内的后台线程承载，MCP 长连接在技能完成后仍可能存在。旧实现没有显式 Web 退出入口，监听端口会继续占用；按端口结束占用进程还会把 MCP 一起关闭。

## 决策

使用独立的编辑器监听管理模块保存 Uvicorn Server、线程和套接字。新增 `cleanup_editor_backend(port=...)` MCP 工具，每轮 Skill 开始前清理旧监听，报告整理完成后再次释放端口。同一轮的人工确认等待和阶段切换继续原会话。清理只操作 Web 生命周期，不修改状态机、授权、参数、成果或持久化草稿；MCP 长连接保持可用，再次打开编辑器时重启监听。MCP 连接正常退出时在 `finally` 中清理自身 Web 服务。

MCP 内嵌服务和独立 `run_web.py` 共用生命周期管理。在数据目录 `editor-backends/` 为每个实例创建独立归属文件，记录项目指纹、实例标识及随机退出凭证；本机身份接口不返回凭证。跨进程清理核对归属记录与当前 HTTP 身份，匹配后使用凭证请求优雅退出，再等待监听实际关闭。按实际监听地址选择 IPv4 或 IPv6，清理覆盖两种回环地址；IPv6 编辑器 URL 使用方括号。请求直连本机地址，不经环境代理或 HTTP 重定向。原有同源与主机检查继续有效。

没有归属记录、身份不一致、凭证错误或退出未完成时报告具体失败，不按端口杀进程。旧版服务无法提供此协议，首次升级需重启旧 MCP 或关闭旧独立 Web。归属路径包含实例标识，退出仅删除本实例文件，不会因跨进程快速重开而删除新实例的记录。归属文件删除失败也不阻止自身套接字和线程资源释放。

## 验证

使用隔离的真实 MCP stdio 与独立 Web 子进程验证：Skill 清理释放端口、会话与 MCP 连接保留、重新打开恢复原会话、跨 MCP 清理旧 Web、独立服务退出、重复清理、无凭证或跨站退出拒绝，以及未知服务继续运行。测试不操作用户当前工程服务。
