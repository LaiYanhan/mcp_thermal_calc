# 基于图2状态机与硬性人工确认守卫机制

为彻底杜绝大模型在调用工具时自说自话、未经确认即推进计算的失控行为，我们依据设计图2构建严格的阶段状态机（State Machine）。状态流转必须经历“场景匹配/提议 $\rightarrow$ 人工确认场景 $\rightarrow$ 参数校验分析 $\rightarrow$ 人工确认参数 $\rightarrow$ 确定性计算 $\rightarrow$ 结构化输出”；各阶段通过 MCP 工具的前置状态守卫强行校验，未获人工确认授权时物理阻断最终计算。

## Considered Options
- **单工具全流程直接执行**：大模型倾向于推测所有未知量并直接输出计算结果，极易产生计算幻觉并剥夺工程师的审核权。
- **纯靠 Prompt 软提示人工审核**：不同大模型对 Prompt 的遵循度不一，无法在代码物理层面保证审核必然发生。
- **带前置守卫的状态机分步工具链（已采纳）**：在 MCP 工具层通过状态转移校验强制中断流程，AI 必须向人类汇报并获得确认才能推进下一步。
