# 节点配置待求参数与全部公式结果输出

本记录补充 ADR 0002，并替代 ADR 0009 中预设独立成果分组的约定。2026-10-16 用户确认：同一代数公式可给定其余变量求解另一个变量；抽屉只增加简洁的待求参数选择；卡片公式显示中文参数名称。所有步骤的实际公式输出均为成果，不再另设成果分组。

## 决策

- `PipelineStep.solve_target` 指定本节点待求的公式变量。省略时使用公式默认输出；`input_map` 绑定其余全部变量，`output_map` 绑定待求变量。不同节点可使用同一公式的不同方向，不改写全局方程。
- 公式层统一提供当前方向的引脚契约。图校验、单位检查、参数检查、拓扑执行和前端变量目录都使用该契约；物性/查表算子保持原有单向契约。
- 现有抽屉增加“本次计算”选择框，选项只显示参数中文名和单位。选择后更新已知量来源。取消不修改工程；保存后撤销旧计算结果与授权，重新核对场景和参数。
- 原待求量变为已知量时，提供一个无默认值的外部输入，用户也可在来源选择中连接已有变量。新待求量原来是独立外部输入时，改为当前节点产出，并保持下游变量引用；原来由另一算子产出时，为当前节点分配独立输出，不覆盖原来源。最终仍由后端执行完整依赖校验。
- 前端卡片显示当前求解方向的中文算式，由公式引脚的 `description` 生成。稳定英文标识保留用于接口和原有代数公式编辑框，显示文本不参与计算。
- 工具目录提供 `variables`（含义、单位、约束）、`default_target`、`solve_targets` 和中文算式。AI 通过同一 `solve_target` 契约编排 Pipeline，遵守原有人工确认流程。
- `PipelineExecutionResult.results` 包含每一步实际输出的 `step_id`、`formula_id`、`formula_name`、`pin`、`variable`、`description`、`unit`、`value`。同一公式多次使用分别记录；中间结果也保留。
- `final_outputs` 是全部计算输出的变量值索引；外部输入及常量仅在 `initial_inputs` 中。删除核心的 `sizing_summary`、`economic_summary`、`sizing_output_keys`、`economic_output_keys`、`output_groups`，旧 JSON 读取时忽略这些分组字段。

## 范围

保留既有模块分层、界面风格和基本错误校验，不扩展全局联立求解、多根选择、缺失业务算子或原始资料差异。公式的输入/输出元数据表示默认方向，不限制节点的其他合法方向。

## 验证

自动化回归覆盖全部参数分别求解、同一公式正反算共存、反算结果向下游传递、单位及依赖错误、数值边界、全部成果与输入隔离、旧数据读取、会话恢复、Web 与 MCP 的确认和执行流程。前端回归覆盖方向切换、来源保留、输出命名冲突和替换节点时保留方向。

真实浏览器完成抽屉切换、保存、确认、填写参数和计算：给定功率 10 MW、焓差 2500 kJ/kg，计算流量 14.4 t/h；下游给定 8 h 计算供汽量 115.2 t。卡片显示反算方向中文算式，输出行保留紫色语义，不再产生独立分组卡片。
